# Test Plan (Vitest)

**Acceptance criteria are defined only in [user-stories.md](user-stories.md).** This plan defines tests (`T-` IDs) and maps each one to the US-, BR-, TC- and EX- IDs it proves. §7 lists every criterion with the tests that cover it.

**Rules**
1. **Independent expectations (TC-04).** Expected figures come only from user-stories.md (Appendix A and the BR tables), which are generated by `tools/reference_values.py --stories`, an exact-fraction calculator that shares no code with the app. **Never regenerate expectations from the app.**
2. **Law changes.** Update tax-rules.md, `tools/rule_checks.py` and `tools/reference_values.py`; rerun them; update user-stories.md Appendix A; then update the tests. EX IDs are append-only and never renumbered.
3. **Status.** A story moves to *Implemented* only when every test mapped to each of its criteria passes **and** the reviewer confirms it manually (§8). Until then it stays *Not implemented*.

**Expected-value fixture.** `python3 -I tools/reference_values.py --json > tests/fixtures/expected.json` writes all Appendix A cases (114 since the engine build) as data. It is generated by the script's own exact-fraction calculator from the verified rule tables, never by app code. The fixture file is created at the start of implementation; the mode exists and has been checked (§9).
- Each case has: `id`, `group`, `taxYear`, `period`, `input` (the string as typed), `annual`, `error` (`null` or `"ABOVE_MAX"`, with `max`), and `result` (`null` on error).
- `result` holds `slab`, `threshold`, `ratePercent`, `baseTax`, `excess`, `marginalTax`, `divisionITax`, `surcharge`, `surchargeApplies`, `taxBeforeRounding`, `taxPayable`, `s219` (`"exact"`, `"dropped"` or `"rounded up"`), `avgMonthlyTax`, `incomeAfterTax` and `avgMonthlyIncomeAfterTax`.
- Each money value is `{exact: "n/d", display: "1,234.50", approx: bool}`. Tests compare `exact` with the app's BigInt rational (cross-multiplication) and `display`/`approx` with the formatter's output. That is one loop over the fixture, with no hand-copied numbers.

## 8. Manual verification by the reviewer (required before Implemented)

For each story, the reviewer runs its criteria by hand in `npm run dev` and checks what automated tests can't judge well. Record the results against the story or TC ID when updating its status in user-stories.md.
- **Visual hierarchy:** annual tax payable is visibly the main result (US-05-AC1). Labels read clearly, notes sit beside the right figures, and ≈ markers are visible.
- **Keyboard and focus (TC-05):** every focused element shows a clear focus ring. Tab order runs year → period → amount → Calculate → Reset → details → sources. Reset returns focus to the amount field.
- **Screen reader (US-11-AC4):** with VoiceOver or NVDA, an error is announced once when shown, and a new result is announced politely.
- **Contrast (TC-05):** body text ≥ 4.5:1 and focus ring/borders of controls ≥ 3:1 (checked with a contrast tool against the ui-design.md tokens).
- **Responsive (TC-05):** at 320, 375, 768 and 1280 px wide, there is no horizontal scroll, the input card and results stay readable, and the slab table either fits or scrolls inside its own container.
- **Zoom:** at 200% browser zoom the layout still works.
